# ผลิตภาพหน้าจอแอปจริงสำหรับ Reel POK-14

คำสั่งต่อเนื่องจากเจ้าของ 2026-11-21: ให้ทีมจัดทำส่วนที่ขาดเอง และล่าสุดเลือก
“ยังไม่ใช้เครดิต ทำภาพหน้าจอก่อน” เสียงไทยจึงพักไว้ ห้ามใช้เครดิต vidIQ หรือซื้อบริการ
ความเห็นนี้ไม่ใช่อนุมัติเผยแพร่สาธารณะ

## เป้าหมายและผู้รับผิดชอบ

CTO รับผิดชอบส่งภาพเคลื่อนไหวจาก Flutter UI จริงให้ Content Marketer ใน POK-14
ผ่าน Engineer – App และ Reviewer / QA ที่มีอยู่ เป็นงานผลิต ไม่ใช่งานตรวจความพร้อมซ้ำ
POK-15 ทำ inventory เสร็จแล้ว แต่ไม่มีใครได้รับมอบหมายสร้าง demo และอัดจอ
CEO ติดตามจนได้ไฟล์ ไม่ส่งคำถามให้เจ้าของหาผู้ถือแท็บเล็ตหรือไฟล์ UI อีก

CTO ให้ Engineer ลงมือใน isolated workspace และตรวจขอบเขตผ่านงานนี้
ไม่ต้องขออนุมัติการผลิต/เลือกสไตล์ซ้ำ ไม่สร้าง agent ใหม่ ไม่แก้โค้ดแทน Engineer
เมื่อเกิดข้อขัดข้องให้ส่งข้อผิดพลาดจริงพร้อมผู้แก้และสิ่งที่ต้องทำ ไม่จบที่แผนหรือเอกสาร

## ขอบเขตที่ทำได้

- ทำ entry point/harness สาธิตเฉพาะเครื่องด้วยข้อมูลสมมติ เพื่อเปิดหน้าโต๊ะ → แตะโต๊ะ →
  รายละเอียด → รายการอาหาร ใช้ widget และหน้าจอจริงจากแอป พร้อมเส้นทางนำทางจริง
- เพิ่มจุด inject แหล่งข้อมูลที่จำเป็นอย่างจำกัด โดยคง production default เดิม
  หรือใช้ Firebase emulator เฉพาะเครื่องหากจำเป็น โดยพิสูจน์การแยกก่อนเริ่มรัน
- ใช้ Android emulator ที่มีอยู่ อัดจอและเก็บพิกัด/เวลาแตะให้ทีมภาพจัดนิ้วตรงปุ่ม
  การอัด emulator เพียงพอสำหรับภาพตัวอย่างนี้ ระบุว่าเป็น emulator ไม่อ้างทดสอบแท็บเล็ตจริง
- ส่ง MP4, PNG ของช่วงสำคัญ, tap-map และหลักฐานที่ดาวน์โหลดได้เป็น Paperclip attachments
  ให้ POK-14 ใช้ประกอบกับ v0.9 มือซ้ายจับขอบและตัวละคร v3 อวบขนนุ่มที่เจ้าของเลือกแล้ว
- เลือกวิธีภายในขอบเขตนี้ได้เอง สร้างและทดสอบ local build ได้ ไม่รอเสียงก่อนทำภาพ

## ข้อจำกัดและสิ่งที่พบแล้ว

- ห้ามเชื่อม production Firebase หรืออ่าน/เขียนข้อมูลร้านจริง ไม่ใช้บัญชีร้านจริง
  ห้ามสร้าง UI สมมติจาก HTML/ภาพวาดแล้วเรียกว่าภาพแอปจริง
- main.dart เดิมเริ่ม DefaultFirebaseOptions.currentPlatform; ShopDatabase ใช้
  FirebaseFirestore.instance และ AuthService.shopId ยังไม่พบ demo switch ครบเส้นทาง
  จึงห้ามรัน entry point production เพื่ออัดจอ
- TablesScreen มี injection สำหรับ tables/open orders/reorder แต่ TableDetailScreen
  ยังเรียก TableService โดยตรง ต้องตรวจทั้งเส้นทาง ไม่ใช่แค่ fixture หน้า grid
- ห้ามแก้ rules, payment mode, App Check, production credentials หรือสิทธิ์ผู้ใช้จริง
  ไม่ deploy/push/merge/release และไม่ติดตั้งบริการเสียเงิน
- Flutter ใช้ C:/Users/Dav/shop_pos/flutter/bin/flutter.bat; Android SDK มีอยู่ที่
  C:/Users/Dav/AppData/Local/Android/Sdk มี AVD API 36 อยู่แล้ว
  เครื่องยังไม่มีอุปกรณ์ adb เชื่อมต่อ ณ การตรวจของ operator
- C: เหลือน้อย ใช้ D: สำหรับ build/cache/AVD writable data และไฟล์ใหญ่ ตรวจพื้นที่ก่อน
  ไม่ลบไฟล์ผู้ใช้เพื่อคืนพื้นที่ หากต้องติดตั้งอะไรเพิ่มรายงานเหตุจริงก่อน
- ใช้ workspace ของงานตนเอง ไม่แก้ checkout Content Marketer/CEO หรือไฟล์งานอื่น
  ถ้า Git metadata ถูก runtime จำกัด ให้ส่ง source diff/zip และหลักฐานให้ CTO/operator
  อย่าหยุดงานอัดจอเพียงเพราะ commit ไม่ได้ และอย่าอ้างว่า commit สำเร็จ

## เกณฑ์รับงาน

1. มี continuous MP4 จากแอปจริง ข้อมูลสมมติทั้งหมด เห็นหน้าโต๊ะ การแตะ และรายละเอียด
   รายการอาหารชัดเจน มีช่วงค้างจอให้ตัดประกอบ 3–7 และ 7–12 วินาทีของ Reel
2. ระบุ branch/commit หรือ source patch, command, demo entry point, seed/fixture,
   การพิสูจน์ว่าไม่เข้าถึง production, emulator/resolution และขอบเขต auth ที่จำลอง
   ไม่อ้างพิสูจน์สิทธิ์บัญชีจริง/การซิงก์จาก harness
3. ระบุพิกัดแตะในขนาดภาพต้นฉบับกับ timestamp แต่ละจุด และ screenshot ก่อน/หลัง
   Content Marketer ต้อง map พิกัดผ่าน crop/scale ลง tablet screen ก่อนจัดนิ้ว
4. Engineer ทดสอบส่วน inject/navigation ที่เปลี่ยนและรัน analysis ที่เกี่ยวข้อง
   QA ตรวจไฟล์ที่เปลี่ยน การแยกข้อมูล และเปิดดู recording จริง รายงานสิ่งที่ยังไม่ได้ตรวจ
5. แนบไฟล์พร้อม SHA-256/provenance ใน Paperclip อ่านกลับได้ แจ้ง POK-14 ให้ทำภาพต่อ
   เมื่อไฟล์พร้อมโดยไม่ต้องรอ Board ตอบคำถามเดิม บันทึก HANDOFF ใน workspace ของตน
