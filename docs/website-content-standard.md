## วิธีใช้และความสัมพันธ์กับแนวทางเดิม

- อ่านร่วมกับ [แกนหลักการพัฒนาเว็บไซต์](website-development-core.md) ก่อนเขียน แก้ ตรวจ หรือเผยแพร่เว็บไซต์การตลาด คู่มือ และบทความ
- เอกสารนี้สรุปมาตรฐานภาษาและเนื้อหาจาก PDF; ดูข้อความตัวอย่างฉบับเต็มและบริบทตามเลขหน้าในต้นฉบับ
- ใช้มาตรฐานภาษาใน PDF นี้เหนือข้อเสนอการใช้คำเก่าที่ขัดกัน ส่วนภาพ สี เส้นทางธุรกิจ และการออกแบบยังอ้างอิงแกนหลักเดิม
- แยก **หลักการเขียน** ออกจาก **ข้อความตัวอย่าง**: ตัวอย่างไม่ได้ยืนยันว่าฟีเจอร์ ราคา หรือเงื่อนไขนั้นเปิดใช้จริงแล้ว
- การบันทึกนี้ไม่ใช่การแก้หรือเผยแพร่เว็บ ตรวจสถานะที่ [HANDOFF](HANDOFF.md) ไม่อนุมานจากเอกสารแนวทาง
- ทบทวนเมื่อจุดยืนผลิตภัณฑ์เปลี่ยน (review 2027-02); ตรวจข้อเท็จจริงที่เปลี่ยนได้ทุกครั้งก่อนใช้ ไม่รอวันทบทวน

จุดที่เอกสารสองชุดต่างกันและต้องรักษาบริบท:

- PDF ให้ภาษาไทยเป็นหลัก ภาษาอังกฤษใช้สนับสนุน; แกนหลักเดิมกำหนดชื่อฟังก์ชันภาษาอังกฤษพร้อมคำอธิบายภาษาไทย จึงใช้คำอธิบายไทยจาก PDF ประกอบได้ โดยยังไม่ถือว่า PDF สั่งยกเลิกชื่อฟังก์ชันภาษาอังกฤษทั้งหมด
- PDF หน้า 13 **เสนอ** Footer 3 กลุ่ม ส่วนแกนหลักเดิมกำหนด 4 กลุ่ม บันทึกทั้งสองแบบไว้ ไม่ถือว่าโครงสร้างเหมือนกันหรือมีการเปลี่ยนหน้าเว็บแล้ว เมื่อลงมือเปลี่ยนโครงสร้างให้ระบุการเลือกให้ชัด ไม่ลบเส้นทาง Solutions หรือ Resources ไปโดยเงียบ ๆ

## 1. จุดยืนและน้ำเสียงแบรนด์ — หน้า 1

Pokpok คือระบบ POS สำหรับร้านค้าปลีกและร้านอาหารไทย ช่วยจัดการงานขาย สินค้าคงเหลือ
การรับชำระเงิน และงานภายในร้านผ่านสมาร์ตโฟนและแท็บเล็ต
ให้เห็นว่าเป็นเทคโนโลยีที่ใช้งานได้จริง เข้าใจร้านค้า และช่วยจัดการงานอย่างเป็นระบบ

- น้ำเสียง **Professional · Clear · Reliable**: มืออาชีพ ตรงประเด็น เชื่อถือได้ พร้อมความเป็นมิตรและความทันสมัย
- สัดส่วนบุคลิกที่เอกสารเสนอ: Professional 70% / Friendly 20% / Technical 10%
- เน้นประโยชน์และสถานการณ์ใช้งาน ใช้ประโยคสั้น แบ่งส่วนอ่านง่าย เจ้าของร้านไม่ต้องมีพื้นฐานเทคนิค
- หลีกเลี่ยงภาษาพูด สำนวนติดตลก และคำโฆษณาเกินจริง เช่น “ดีที่สุด” “ครบทุกอย่าง” “เปลี่ยนธุรกิจได้ทันที” หากไม่มีหลักฐาน
- ระบุข้อจำกัดของฟังก์ชันและแพ็กเกจอย่างชัดเจน ไม่ใช้ภาษาทางการจนเข้าถึงยาก

## 4. แนวทางเนื้อหาแต่ละหน้า — หน้า 3–9

**ข้อความด้านล่างเป็นข้อเสนอจาก PDF ต้องตรวจฟังก์ชันและเงื่อนไขก่อนนำขึ้นเว็บ**

| หน้า/ส่วน | ทิศทางและตัวอย่างข้อความ |
| --- | --- |
| Hero หน้าแรก | “จัดการหน้าร้านและหลังร้านอย่างเป็นระบบ ด้วย Pokpok POS” ตามด้วยคำอธิบายประเภทแอป งานที่ช่วยทำ และการเลือกฟังก์ชันตามแพ็กเกจ |
| ภาพรวมผลิตภัณฑ์ | “จัดการงานร้านค้าในแอปเดียว” พร้อมทางไปดูฟังก์ชันตามประเภทร้าน |
| สั่งซื้อสินค้า | “สั่งซื้อสินค้าเพื่อเติมสต็อกร้าน” อธิบายสินค้า ราคา จำนวนขั้นต่ำ และผู้จำหน่ายที่เข้าร่วม |
| คู่มือ | “คู่มือการใช้งาน ตั้งแต่ตั้งค่าร้านจนถึงปิดยอด” ครอบคลุมตั้งค่าร้าน เพิ่มสินค้า เปิดรอบ รับชำระเงิน และตรวจยอดขาย |
| หน้าฟังก์ชัน | “ฟังก์ชันสำหรับการบริหารจัดการร้านค้า” อธิบายผ่านงานจริงในแต่ละวัน |
| ฟังก์ชันร้านค้าปลีก | การขาย/ใบเสร็จ/ประวัติ การรับสินค้า/สินค้าใกล้หมด การติดตามยอดค้างชำระและรับชำระภายหลัง |
| ฟังก์ชันร้านอาหาร | รายการอาหารและหมายเหตุในโต๊ะ การส่งครัวและติดตามสถานะ การจัดการบิลและการชำระเงิน |
| สั่งซื้อออนไลน์ | “เปิดรับคำสั่งซื้อออนไลน์ แม้ลูกค้าไม่ได้อยู่ที่ร้าน” อธิบายแชร์ลิงก์ผ่าน LINE/Facebook และจัดการออเดอร์ในแอป |
| รายงานและสินค้า | “ตรวจสอบยอดขายและบริหารสินค้าคงเหลือ” ระบุแพ็กเกจและสิทธิ์ที่รองรับ รวมถึงเงื่อนไขการเปิดใช้ประวัติความเคลื่อนไหว |
| หน้าราคา | “แพ็กเกจและราคาบริการ Pokpok POS” ช่วยเลือกตามงานร้าน ไม่ใช่เพียงรายการฟีเจอร์ยาว ๆ |

ลำดับงานตัวอย่าง: รับรายการขาย → จัดเตรียมสินค้าและรายการอาหาร → ดำเนินการชำระเงิน → ตรวจสอบยอดขายประจำวัน

ตัวอย่างการอธิบายแพ็กเกจ **ร้านค้าปลีก** ในหน้า 7–8:

- **Solo:** จัดการการขายและตรวจสอบยอดขายประจำวัน สำหรับร้านขนาดเล็กที่เจ้าของดูแลเอง
- **Lite:** จัดการสินค้าคงเหลือและติดตามยอดค้างชำระ
- **Full:** บริหารร้านด้วยข้อมูลและรายงานเชิงลึก รวมตัวอย่างเรื่องพนักงาน สมาชิก และการวิเคราะห์

รายการนี้เป็นร่างข้อความ ไม่ใช่ตารางสิทธิ์จริง และไม่ควรนำไปใช้กับร้านอาหารทั้งชุดโดยไม่ตรวจสอบ
ตั้งชื่อรายการฟีเจอร์ให้ชัด เช่น “รายงานสรุปยอดขายประจำวัน” “ระบบสมาชิกและสะสมคะแนน”
และ “จัดการยอดค้างชำระและบันทึกการรับชำระ”

ส่วนค่าใช้จ่ายให้แยกค่าซอฟต์แวร์ อุปกรณ์ และค่าธรรมเนียมผู้ให้บริการชำระเงินภายนอกตามเงื่อนไขจริง
ส่วนช่วยเหลือให้ขอขั้นตอนที่พบปัญหา รุ่นแอป และภาพหน้าจอผ่าน LINE โดยปิดบังข้อมูลส่วนบุคคลก่อนส่ง

## 5. FAQ — หน้า 9–10

ครอบคลุมประเภทธุรกิจ อินเทอร์เน็ต/ออฟไลน์ การเปลี่ยนอุปกรณ์หรือติดตั้งแอปใหม่
การเริ่มทดลองใช้ การหมดอายุแพ็กเกจและข้อมูลร้าน และค่าธรรมเนียมชำระเงินออนไลน์

- ตอบตรงคำถามตั้งแต่ประโยคแรก กระชับ ระบุเงื่อนไข และใช้ลำดับข้อเมื่ออธิบายขั้นตอน
- เรื่องข้อมูลต้องแยกข้อมูลที่ซิงก์แล้วกับที่ยังอยู่บนเครื่อง ไม่รับประกัน “ข้อมูลไม่หาย” โดยไม่มีหลักฐาน
- เรื่องออฟไลน์ให้ระบุสิ่งที่ทำได้ ระยะเวลาที่รองรับ และสิ่งที่ต้องใช้อินเทอร์เน็ตจากระบบจริง
- อธิบาย APK/TestFlight และสถานะ iOS ตามช่องทางที่เปิดใช้จริง
- เรื่องหมดอายุและค่าธรรมเนียมต้องตรงกับนโยบายปัจจุบัน ไม่คัดลอกคำตอบตัวอย่างเป็นคำรับรอง

## 7. SEO — หน้า 11–12

ใช้คำค้นเกี่ยวกับโปรแกรม POS ระบบขายหน้าร้าน ร้านค้าปลีก ร้านอาหาร สินค้าคงเหลือ
การจัดการโต๊ะ/ออเดอร์ และรายงานยอดขายอย่างเป็นธรรมชาติ ไม่ยัดคำค้นจนอ่านยาก
แต่ละหน้ามี Title และ Meta Description เฉพาะ สอดคล้องกับเนื้อหาจริง

ตัวอย่าง Title ในต้นฉบับ:

- หน้าแรก: “Pokpok POS | โปรแกรมขายหน้าร้านสำหรับร้านค้าปลีกและร้านอาหาร”
- ฟังก์ชัน: “ฟังก์ชัน Pokpok POS | ระบบขายสินค้า สต็อก และจัดการออเดอร์”
- ราคา: “ราคา Pokpok POS | เปรียบเทียบแพ็กเกจ Solo, Lite และ Full”

Meta Description สรุปประโยชน์และขอบเขตของหน้านั้น ตรวจเงื่อนไขทดลองใช้และแพ็กเกจก่อนใส่ตัวเลข
ใช้ Alt Text อธิบายสิ่งที่อยู่ในภาพจริง และคงแนวทาง H1/หน้าธุรกิจ/Internal Linking จากแกนหลักเดิม

- **“พนักงาน 3 บัญชี”**: ต้องยืนยันว่าเป็นบัญชีทั้งหมดหรือพนักงานเพิ่มจากเจ้าของ ก่อนเขียนข้อความ (หน้า 9)
- อุปกรณ์พิมพ์ใบเสร็จ ช่องทางชำระเงิน และความพร้อม Android/iOS
- พฤติกรรมออฟไลน์ การซิงก์ การติดตั้งใหม่ และนโยบายข้อมูลหลังแพ็กเกจหมดอายุ
- ราคา รอบชำระเงิน ค่าอุปกรณ์ ค่าธรรมเนียมภายนอก เงื่อนไขสมัครและทดลองใช้

ตัวเลข **60 วัน**, **เริ่มต้น 199 บาท/เดือน**, เงื่อนไข **ไม่ต้องผูกบัตร** และฟีเจอร์ในตัวอย่าง
เป็นข้อมูลที่ต้องตรวจ ณ วันที่เผยแพร่ ไม่ใช่การสั่งเปลี่ยนราคา/สิทธิ์ในระบบ
แยกฟีเจอร์ที่เปิดใช้จริง Test Mode และแผนในอนาคต ตามจุดตรวจของแกนหลักเดิม

## 9. Footer — หน้า 13

คำอธิบายแบรนด์ต้องบอกว่าเป็น POS สำหรับร้านค้าปลีกและร้านอาหารไทย ใช้บนสมาร์ตโฟน/แท็บเล็ต
จัดการงานขาย สินค้าคงเหลือ และคำสั่งซื้อ โดยฟังก์ชันขึ้นกับรูปแบบธุรกิจและแพ็กเกจ

รายการนำทางที่ PDF เสนอ:

- **ผลิตภัณฑ์:** ฟังก์ชัน แพ็กเกจและราคา คู่มือ บทความ สั่งซื้อสินค้าเข้าร้าน
- **ติดต่อ:** อีเมล และ LINE Official
- **ช่วยเหลือ:** FAQ นโยบายความเป็นส่วนตัว เงื่อนไขการใช้บริการ

นี่คือข้อเสนอสามกลุ่มจาก PDF; ดูหมายเหตุเรื่องความต่างกับโครงสร้างสี่กลุ่มในหัวข้อวิธีใช้

## 10. ตรวจรับเนื้อหาก่อนเผยแพร่ — หน้า 13–14

- **แบรนด์:** น้ำเสียงตรงแนวทาง คำศัพท์สม่ำเสมอ ไม่มีคำโฆษณาเกินหลักฐาน
- **ความถูกต้อง:** ฟีเจอร์/สิทธิ์ ราคา รอบชำระ ทดลองใช้ ช่องทางและค่าธรรมเนียมตรงระบบและนโยบาย ทีมผลิตภัณฑ์ยืนยันส่วนที่เกี่ยวข้อง
- **การใช้งาน:** หัวข้อเข้าใจทันที คำอธิบายไม่ซ้ำซ้อน ปุ่มชัดและตรงปลายทาง อ่านบนมือถือได้ง่าย
- **SEO:** Title เฉพาะหน้า Meta ตรงเนื้อหา คำค้นเป็นธรรมชาติ หัวข้อไม่ซ้ำโดยไม่จำเป็น Alt Text ตรงภาพ
- **ตรวจสุดท้าย:** สะกดและเว้นวรรคไทย/อังกฤษ ลิงก์และ CTA ทุกจุด การแสดงผล Desktop/Mobile

## 11. หลักตัดสินข้อความ — หน้า 14

“สื่อสารเทคโนโลยีให้เข้าใจง่าย และสื่อสารประโยชน์ของระบบให้เห็นภาพจากการใช้งานจริง”

ทุกข้อความควรตอบอย่างน้อยหนึ่งข้อ: Pokpok คืออะไร / ช่วยจัดการงานอะไร / เหมาะกับร้านใด /
ฟังก์ชันอยู่ในแพ็กเกจใด / ผู้ใช้งานควรทำอะไรต่อ
ถ้าไม่ช่วยให้เข้าใจผลิตภัณฑ์ เลือกแพ็กเกจ หรือเริ่มใช้งานได้ง่ายขึ้น ให้พิจารณาปรับหรือตัดออก
