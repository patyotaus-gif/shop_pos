# แกนหลักการพัฒนาเว็บไซต์ Pokpok

สถานะ: แนวทางที่เจ้าของยืนยันเมื่อ 11 พฤศจิกายน 2026 สำหรับงานเว็บไซต์ต่อจากนี้

ที่มา: เจ้าของระบุว่า “สิ่งที่ให้ดูต่อไปนี้คือแกนหลักในการพัฒนาเว็บไซต์บันทึกไว้ด้วย”
พร้อมภาพ `Screenshot 2026-11-11 130148.png`, `130207.png`, `130226.png` และ `130240.png`
เอกสารนี้เรียบเรียงข้อเสนอทั้ง 10 จุดจากภาพ โดยรวมส่วนที่ซ้ำกันไว้ครั้งเดียว
ภาพเว็บอ้างอิงใช้สื่อทิศทางภาพลักษณ์ ไม่ใช่สิทธิ์ให้คัดลอกงานของเว็บอื่น

## วิธีใช้

- อ่านก่อนวางแผน แก้ ตรวจ หรือเผยแพร่เว็บไซต์การตลาดของ Pokpok รวมถึงหน้าธุรกิจ ราคา คู่มือ และบทความ
- ใช้เป็นแนวทางหลักเหนือข้อเสนอเว็บไซต์เก่าที่ขัดกัน จนกว่าเจ้าของจะเปลี่ยนทิศทางอย่างชัดเจน
- เอกสารนี้กำหนดสิ่งที่ต้องการ ไม่ใช่รายงานว่าสร้างครบแล้ว ตรวจสถานะงานจาก `docs/HANDOFF.md`
- งานนี้บันทึกทิศทางเท่านั้น ไม่ได้อนุมัติการเผยแพร่หรือเปลี่ยนราคา
- ทบทวนเมื่อเปลี่ยนกลุ่มเป้าหมายหรือจุดยืนผลิตภัณฑ์ (review 2027-02)
- รักษาเอกสารให้สั้นพออ่านครบในหนึ่งครั้ง: งบเนื้อหา 1,800 คำที่คั่นด้วยช่องว่าง; รายละเอียดการลงมือและหลักฐานทดสอบอยู่ในเอกสารงานแต่ละรอบ

## 1. Hero Section — อ่านแล้วรู้ทันทีว่าเป็นอะไร

ข้อความเดิม “หน้าร้านก็ต้องดู หลังร้านก็ต้องรู้ ให้ Pokpok ช่วยจด” ยังไม่ตอบครบว่า
Pokpok คืออะไร เหมาะกับใคร และทำไมต้องเลือกใช้

- Headline บอกประเภทผลิตภัณฑ์ให้ชัดว่าเป็นซอฟต์แวร์/แอป POS
- Subtitle อธิบายประโยชน์ด้วยภาษาไทยที่เข้าใจง่าย ไม่ใช้ศัพท์เทคนิคมากเกินไป
- CTA หลักใช้สี Burgundy เพื่อดึงสายตา
- ใช้ Product Mockup ที่เห็นหน้าจอแอปจริง พร้อมภาพ Tablet หรือ Smartphone เพื่อสื่อการใช้งานระบบ POS
- สโลแกนใช้ประกอบได้ แต่ไม่ทำหน้าที่แทนคำอธิบายผลิตภัณฑ์

## 2. Visual Identity และ Mood & Tone

- ใช้ภาพถ่ายจริง ภาพหน้าจอระบบจริง และภาพอุปกรณ์หรือเทคโนโลยีที่เกี่ยวข้อง
- ใช้พื้นหลังสีขาวและเทาอ่อนเป็นหลัก
- ใช้ Burgundy เป็นสีเน้น ไม่ใช้เต็มพื้นที่ทุก Section
- ภาพสินค้าและอาหารที่เห็นในร้านเดโมควรมีแสง สี และรูปแบบไปในทางเดียวกัน เพื่อให้ภาพหน้าจอดูเป็นชุด

## 3. แบ่งเส้นทางตามกลุ่มลูกค้า

แบ่งให้เห็นตั้งแต่ต้นเว็บไซต์เป็น 2 เส้นทาง:

- **RETAIL SOLUTIONS** สำหรับร้านค้าปลีก
- **RESTAURANT SOLUTIONS** สำหรับร้านอาหารและคาเฟ่

เมื่อคลิก ให้ไปหน้าเฉพาะของแต่ละธุรกิจ ไม่ใช่เพียงเลื่อนไปส่วนหนึ่งของหน้าเดียวกัน
แต่ละหน้ามี Hero, ปัญหาของธุรกิจนั้น, ฟังก์ชันที่เกี่ยวข้อง, ภาพหน้าจอจริง,
แพ็กเกจที่เหมาะสม และ CTA เฉพาะกลุ่ม

## 4. Product Features — แสดงว่าระบบทำงานอย่างไร

ไม่หยุดที่การบอกว่าระบบ “ทำอะไรได้” แต่แสดงการใช้งานและผลลัพธ์ที่ลูกค้าได้รับ
แต่ละฟังก์ชันประกอบด้วย 4 ส่วน:

1. ชื่อฟังก์ชันภาษาอังกฤษ
2. คำอธิบายภาษาไทยที่เข้าใจง่าย
3. ภาพหน้าจอจริงหรือ Product Mockup
4. ประโยชน์ที่ลูกค้าจะได้รับ

หน้าแรกเลือกฟังก์ชันสำคัญ 3–4 รายการ พร้อมปุ่มดูรายละเอียดเพิ่มเติม
ไม่จำเป็นต้องใส่ทุกฟังก์ชันในหน้าแรก

หมายเหตุการตัดสินใจ: รูปแบบชื่ออังกฤษพร้อมคำอธิบายไทยข้างต้นเป็นแนวทางล่าสุดที่เจ้าของรับรอง
เหนือบันทึกแผนเก่าที่ระบุ “Thai names first”; ยังไม่ถือว่าหน้าเว็บปัจจุบันเปลี่ยนตามแล้ว

## 5. Pricing Section — เลือกและเปรียบเทียบได้ทันที

- แยกแพ็กเกจร้านค้าปลีกและร้านอาหารให้เห็นความต่างชัดเจน
- แต่ละแพ็กเกจบอกว่าเหมาะกับร้านประเภทใด และเพิ่มฟังก์ชันใดจากแพ็กเกจก่อนหน้า
- ใช้ Pricing Card ที่อ่านง่ายและเปรียบเทียบกันได้
- มีตัวเลือก Monthly / Yearly ที่เห็นชัด
- แสดงราคาต่อเดือนและราคาที่เรียกเก็บรายปีอย่างชัดเจน ไม่ทำให้ค่าเฉลี่ยต่อเดือนสับสนกับยอดชำระจริง
- เน้นฟังก์ชันที่แตกต่างกันจริง และมี CTA ให้ทุกแพ็กเกจ
- อธิบายเงื่อนไขทดลองใช้ฟรีและการเริ่มชำระเงินอย่างเด่นชัด

## 6. สร้างความน่าเชื่อถือด้วยหลักฐาน

- ใช้ภาพหน้าจอแอปจริง พร้อมคำอธิบายว่าหน้านั้นทำอะไร
- แสดงการใช้งานจริงในร้าน เช่น รับออเดอร์ คิดเงิน และจัดการสต็อก
- ให้ข้อมูลเวอร์ชันแอป ระบบปฏิบัติการ และอุปกรณ์ที่รองรับ
- แสดงช่องทางติดต่อและวิธีขอความช่วยเหลือให้ชัดเจน
- ภาพหรือข้อมูลสาธิตต้องแยกจากหลักฐานลูกค้าใช้งานจริง ไม่ใช้แทนคำรับรองจากลูกค้า

## 7. CTA และเส้นทางการตัดสินใจ

| ตำแหน่ง | การกระทำที่เสนอ |
| --- | --- |
| Hero | เริ่มทดลองใช้ฟรี |
| หลังแนะนำฟังก์ชัน | ดูวิธีใช้งาน |
| หลังแสดงราคา | เลือกแพ็กเกจ |
| ก่อน Footer | ทดลองใช้กับร้านของคุณ |

มีทางเลือกสำหรับคนที่ยังไม่พร้อมสมัคร เช่น ปรึกษาทีมงาน ดูตัวอย่างหน้าจอ
และสอบถามว่าแพ็กเกจใดเหมาะกับร้าน

การติดตั้ง APK และการติดตั้งผ่าน TestFlight มีขั้นตอนมากกว่าการสมัครเว็บทั่วไป
จึงควรมีคู่มือภาพทีละขั้น และระบุสถานะ iOS ที่เป็นรุ่นทดสอบให้ชัดตามสถานะจริง ณ วันที่เผยแพร่

## 8. Mobile Responsive Design

- Navigation ไม่แน่นเกินไป
- Hero อ่านได้โดยไม่ต้องซูม
- CTA มีขนาดเหมาะกับการสัมผัส
- Pricing Card แสดงทีละแพ็กเกจได้ชัดเจน
- Product Mockup ไม่ถูกตัดส่วนสำคัญ
- ตารางเปรียบเทียบใช้งานบนจอเล็กได้
- ปุ่ม LINE และช่องทางติดต่อเข้าถึงง่าย

## 9. SEO และโครงสร้างเนื้อหา

ทำให้ทั้งคนอ่านและระบบค้นหาเข้าใจว่า Pokpok เป็นซอฟต์แวร์ POS และเหมาะกับธุรกิจประเภทใด

- กำหนด Title Tag และ Meta Description แยกแต่ละหน้า
- ใช้ H1 เป็นหัวข้อหลักที่ชัดเจน
- เพิ่ม Alt Text ให้ภาพตามเนื้อหาของภาพ
- สร้าง Landing Page เฉพาะแต่ละประเภทธุรกิจ
- เพิ่มบทความความรู้เกี่ยวกับการบริหารร้าน
- ใช้ Internal Linking เชื่อมบทความ ฟังก์ชัน และหน้าเฉพาะธุรกิจ

ตัวอย่างหัวข้อจากข้อเสนอ:

- POS คืออะไร และเหมาะกับร้านแบบไหน?
- วิธีจัดการสต็อกสินค้าในร้านค้าปลีก
- ระบบจัดการออเดอร์ช่วยร้านอาหารอย่างไร?
- เลือกโปรแกรม POS อย่างไรให้เหมาะกับธุรกิจ?

## จุดตรวจเมื่อนำไปพัฒนาจริง

ส่วนนี้เป็นแนวทางตรวจรับประกอบ ไม่ใช่ข้อเสนอเพิ่มเติมที่อ้างว่ามาจากภาพ:

- ตรวจฟีเจอร์ ราคา เงื่อนไขทดลองใช้ ช่องทางชำระเงิน เวอร์ชัน และการรองรับอุปกรณ์จากระบบปัจจุบันก่อนเขียนคำโฆษณา
- แยกสิ่งที่เปิดใช้จริง สิ่งที่ยังเป็น Test Mode และสิ่งที่ยังอยู่ในแผนให้ชัดเจน
- ใช้ภาพที่มีสิทธิ์ใช้งาน และข้อมูลร้านเดโมที่อนุญาตให้เผยแพร่ หลีกเลี่ยงข้อมูลส่วนตัวในภาพหน้าจอ
- ตรวจลิงก์ CTA เส้นทาง Retail/Restaurant ราคา และหน้าติดตั้งบนมือถือและจอใหญ่
- บันทึกว่าแต่ละรอบทำข้อใดแล้ว ข้อใดยังเหลือ พร้อมผลตรวจจริงใน `docs/HANDOFF.md`
